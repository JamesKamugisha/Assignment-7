
(1) UDP does not guarantee that messages will be delivered. If a message from the client to the server is lost, the server will not receive the move, so the game will not update. The client may continue waiting for a response. If a message from the server to a client is lost, that client will not receive the updated board and may remain waiting. Our program does not resend lost messages, so the game may get stuck.
(2) Our save and load system has some limitations. If the server crashes while writing a file, the saved data could be incomplete or corrupted. The program also depends on the save files being available and readable. If a file is missing or damaged, recovery may fail. We save the game data and player addresses in separate files, so a crash between saving these files could leave them inconsistent. The system also does not handle client disconnections or changes in client network addresses after restarting.
